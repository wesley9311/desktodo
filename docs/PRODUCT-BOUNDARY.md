# 数据边界与产品取舍

> 写给决策用。四件事：**哪里能碰、谁能授权、你自己数据说了什么、怎么让你能骂我**。
> 日期 2026-11-05。所有"当前状态"都是真机读出来的，不是设想。

---

## 0. 一句话

这产品的价值不在"我知道你干了什么"，在**"我给你报的数，你能反驳"**。
所以接入的数据只要满足一个条件：**能让用户发现自己记错了**。满足不了的，一个都不要。

---

## 1. 红线先划：五档数据，只有三档该碰

按侵入程度分档。判断标准是**"这数据泄露后用户会不会后悔装了它"**。

| 档 | 内容 | 要不要 | 理由 |
|---|---|---|---|
| **L0** | 用户自己敲进来的待办、完成、放弃、项目 | **要**（已有） | 本来就属于产品，不涉及他人 |
| **L1** | 系统状态：前台是哪个 App、键鼠空闲多久、锁屏/睡眠 | **要**（部分已有） | 零权限、无内容、只说"在哪、在不在" |
| **L2** | 用户主动授权后给的**结构化数据**：日历、提醒事项 | **要**（已接） | 用户能理解"为什么要给"，且能随时在系统设置里掐 |
| **L3** | 系统自己的使用记录：屏幕使用时间（knowledgeC.db） | **可选，默认关** | 需要完全磁盘访问，等于把整个磁盘的门开给一个待办 app。**必须用户主动去开，不能诱导** |
| **L4** | **内容级**：窗口标题、剪贴板、文件内容、摄像头画面、键盘输入 | **永不做** | 一旦能读，产品性质就从"记录我做的事"变成"记录我在看什么/说什么"。用户的恐惧是对的，不该被"优化体验"说服 |

### 为什么 L4 是死线而不是"谨慎使用"

L2/L3 拿到的是**元数据**（几点有个会、今天用了多久 Slack）。
L4 拿到的是**内容**（这个会的标题是"和 X 谈离职"、这个窗口是"体检报告.pdf"）。

元数据泄露：别人知道你忙。
内容泄露：别人知道你在慌什么。

一个待办 app 没有任何正当理由需要后者。**能力本身就是负债**——一旦代码里存在这个读取路径，它就有被误开、被日志打印、被同步上云的可能。所以不是"默认关"，是**不写这段代码**。

### 2.2 关于"屏幕距离"，把话说透

你上次问近视的事，我说"Mac 没有测距硬件"。更准确的说法是：

**能测，但只有一条路——摄像头**（Vision 框架做人脸框尺寸估算）。代价是：
- 要摄像头权限，且必须**常开**才能连续测距；
- 一个桌面待办 app 常开摄像头，是这个产品最不该干的事；
- 精度受光照/角度影响，测出"62cm"这种数字会给人虚假的安全感。

**真正解决近视的是字号，不是距离。** 已实现的部分（4 档视图缩放 + 窗口同步放大，100/115/130/150）比任何距离提醒都直接：看不清就调大，不用把脖子伸过去。这条已经落地了。

### 2.3 可测试授权清单（每项 30 秒验证真拿到了）

"授权了"和"拿到了"是两件事。下表左列是操作，右列是**不改代码就能验证**的方法。

| 权限 | 授予路径 | 授予成功的硬证据 | 撤销后应该怎样 |
|---|---|---|---|
| 日历 | 系统设置 → 隐私与安全性 → 日历 → 勾选「浮窗待办」 | `/tmp/desktodo.log` 出现 `ext cal=ok/…`；年轮页出现「日历 N 项」行 | 行整条消失，退成可点的「授权后显示日历」 |
| 提醒事项 | 隐私与安全性 → 提醒事项 | `ext rem=ok/…`；今日页出现「提醒事项今天到期 N 件」 | 同上 |
| 完全磁盘访问 | 隐私与安全性 → 完全磁盘访问 → 拖入 app | `ext screen=ok` 且 `apps` 非空；今日页从「前台」变「屏幕」 | 变 `nofda`，退回「前台」口径，**不写 0** |
| 重置某个权限（测试用） | 终端 `tccutil reset Calendars local.desktodo.app` | 重启后日志回 `ask`，界面出现授权提示 | —— |

**测试要点（都会真的测，不靠肉眼猜）**：
1. `tccutil reset` 三者全部重置 → 冷启动 → 应出现两条可点提示，**不得有任何伪造数字**。
2. 删掉 `knowledgeC.db` 的读权限（或改名）→ 应报 `nofile`，界面退回「前台」口径。
3. 把系统日期改到 12/21 → 应自动出现年轮公告（已支持注入日期测试）。
4. 断网 → 天气消失，其余数字照常（**核心数据不依赖网络**）。

## 3. 你自己的数据说了什么（不是类型学，是实测）

看了 `data.json`（10 个节点、1 天账本、6 条流水）。样本很小，但**模式已经很清楚**，而且和"正常人会用成什么样"高度一致：

### 3.1 你是"盘点式"用，不是"流水式"用

```
11-04 15:57–16:19  22 分钟内建了 10 条（含 2 个项目文件夹）
11-05 13:14–13:17   3 分钟内勾掉 6 条
```

不是"想到就记一条"，是**坐下来一次性清仓**。这对产品的含义：
- 不要为"随时快速记录"过度优化（那是另一类产品）；
- 要做的是**清仓时刻的体验**：一次能勾一串、勾完有结算感；
- 年报的意义也在这里——它是"清仓记录"的年汇总，不是"工作流水"。

### 3.2 `due` 是系统自己写的，不是你定的

7 条任务里 6 条 `due` 是同一天 `2026-11-05 00:00`。

**先纠正我自己**：我上一稿写的是"你把 due 当标签用"——那是我猜的，不是事实。
读了代码才看清：新建任务时 `due` 自动等于**创建当天**，跨夜没做完就自动被推到今天，
并给 `carried` 加一笔顺延天数。用户从头到尾没有设置过它。

所以 `due` 只回答一个问题：**"这件事现在排在哪天"**。它不回答"我打算哪天做"。

结论比我原来写的更强：**`due` 绝对不能进任何历史统计**。
它每天都会被 rollover 改写——今天去看"3 月 2 日该做几件"，读到的是被改写过的今天，
等于拿今天的排期伪造昨天的计划。零回填不是洁癖，是这个字段的物理性质决定的。

顺带：真正能反映拖延的是 `carried`（顺延天数），不是 `due`。它没被任何界面读到，目前只在数据里躺着。

### 3.3 `remindAt` 才是你自己设的，而且用法很明确

两个 `remindAt` 分别是创建后 **~32 分钟**、**~13 分钟**。
也就是你把提醒当**"过一会儿叫我"**用，不是"截止日期"。

那上一稿说"两个字段语义打架"也不准确：`due` 是系统排期，`remindAt` 是你要的响铃时刻，
分工本来清楚。真正的问题是**界面上只有一个"提醒"入口**，用户看不到 `due` 在背后被改写——
哪天要显示"这件事排了几天"，得先把这个机制说给用户听，否则他会以为自己设的日期被偷偷改了。

### 3.4 有一类条目永远勾不掉

节点 47：`ScreenShot_2026-07-19_232257_437`，从 Finder 拖进来的，带原始文件名，**一直未完成**。
这是"文件入口被顺手当待办"的典型：拖进来看一眼，不会勾，然后它永远躺在列表里。
现在的 `staleCount(7)` 会在提示里说"还有 N 件躺了一周"，但**没有给"这类东西一键归档"的出口**。

### 3.5 完成率 6/7，但完成时间全挤在 3 分钟内

账面完成率 86%，可是这 6 条全在同一分钟段勾掉。
**用"完成时间"算工作节奏会得出完全错误的结论**（"你 13:14 效率最高"）。所以日报不能按小时画柱，只能按天——这条已经是现状，但要写下来防止以后犯。

### 3.6 删除动作 = 0

`flow` 是空的——你一次都没"删掉未完成"。不是没僵尸任务（47 就是），是**不敢删**。
所以"删除记放弃"这个设计是对的：用户需要的是"承认这件事我不做了"，不是"假装它没存在过"。

## 4. 痛点 → 产品动作（哪些已做、哪些该做、哪些不做）

| 痛点（真实行为） | 现在的做法 | 判断 |
|---|---|---|
| 批量录入，事后清仓 | 回车即存、勾选即结算 | ✅ 够用 |
| `due` 当标签用 | 不拿 due 做任何历史推断 | ✅ 已守住 |
| 提醒当"过会儿叫我" | due 与 remindAt 两个字段并存 | ⚠️ 该合并（低成本） |
| 拖进来的文件勾不掉 | `staleCount` 会在提示里点名 | ⚠️ 缺"归档掉这类"的出口 |
| 不敢删，僵尸堆积 | 删除记「放弃」、永久账本 | ✅ 已有 |
| 完成时间被误读 | 只按天聚合，不按小时 | ✅ 已有 |
| 年报数字没感觉 | 少而具体（最长连续、动手的天） | ✅ 已有 |
| 近视/前倾看屏 | 4 档视图缩放 + 窗口同步放大 | ✅ 已有 |
| **不知道我报的数对不对** | —— | ❌ **缺，见第 5 节** |

第 5 节是这份文档的重点：**目前产品没有任何"用户能否决我"的通道**。
一个声称"绝对真实"的产品，如果用户无法指出哪句不准，那"真实"就只是我的自我声明。

## 5. 让你能纠正我：三层否决权（已实现，见第 7 节）

设计原则：**不靠你写长反馈，靠一次点击**。三次点击以内的反对才有意义。

### 第 1 层｜行级「不对」

每一条外部数据行（`日历 2 项 · 3 小时 · 2 天有会`）行尾有一个 `?`，默认 `opacity .3`，鼠标经过才显形。

点开后只有三个选项：

```
  日历 2 项 · 3 小时 · 2 天有会 · 另有 50 个全天     ?
  ┌────────────────────────────────────┐
  │ 数不对   不该显示   没事            │
  └────────────────────────────────────┘
```

- **数不对** → 记一条 `{k:'cal.n', 我给的:2, 时间}`
- **不该显示** → 这一行永久隐藏（`state.hide['cal']=1`），菜单「数据来源」里能恢复
- **没事** → 什么都不记

存本地 `state.fb[]`，**不联网、不上报**。菜单里能看到"你纠正过我 12 次"。

### 第 2 层｜日级对账

触发条件（三个同时满足，否则闭嘴）：
当天日历有 ≥2 个日程 **且** 账本当天 0 件 **且** 当天还没问过。

```
  今天日历上有 3 个日程，账本 0 件。
  [ 没做事 ]  [ 忘了记 ]  [ 别问 ]
```

- **没做事** → 记 `gap[d]=0`，年报里"动手的天"如实算 0 天
- **忘了记** → **不自动补数**，记 `gap[d]=1`，年报里那句"动手的天"后面加一个诚实的括号：`（其中 2 天可能漏记）`
- **别问** → 14 天内不再问

关键点：**"忘了记"绝不替我补数据**。补了就回到自欺。只标记"这天不确定"，让数字自己带瑕疵。

### 第 3 层｜月级否决（最重要）

每月 1 号，报告卡底部出现一条：

```
  上个月我说过这些话，哪些不准？
  日均 2.8 件           [准] [不准]
  有会反而做得多        [准] [不准]
  最长连续 5 天         [准] [不准]
```

要能做到，得在**生成判断时**就把它存档：

```js
state.said['2026-11'] = [
  { k:'avg',  t:'日均 2.8 件' },
  { k:'meet', t:'有会反而做得多' }
];
```

规则：**同一类判断累计 2 次"不准" → 该类永久降级为"只给数，不给话"**。

这条是整个"真实性"承诺的闭环：
- 你说我不准，我下一次就不说这种话；
- 不是"我会努力准确"，是**"不准的话会被你说到消失"**。

### 实现成本

| 层 | 改动 | 预估 |
|---|---|---|
| 1 行级 | `renderReport` 每行加 button + 事件委托 + `state.fb` + 隐藏表 | 小（半天内） |
| 2 日级 | 一个 `maybeAskGap()`，条件严格，加一个 `.ask` 面板 | 小 |
| 3 月级 | 生成时存档 `said` + 月初加载 + 计数降级 | 中（要动 tip* 系列函数） |

三层都不需要任何新权限，全部本地。**这是唯一一条"加了只会更诚实、不会更侵入"的功能。**

## 6. 技术债（会在你面前爆的）

1. **ad-hoc 签名 → 每次重装权限清零**
   签名要求是 `cdhash H"..."`，重编译就变。今天重装 8 次，日历授权归零 8 次。
   **解法**：登录钥匙串建一个固定自签证书，签一次永久有效。要动钥匙串，等你点头。

2. **`knowledgeC.db` 的 schema 会变**
   苹果每次大版本可能改表结构。现在有 `noschema` 降级，但要接受**某次系统更新后这个功能静默失效**，不能崩、不能写 0。

3. **屏幕使用时间有延迟**
   系统不是实时写库，通常滞后 1–2 小时。今日页显示"屏幕 3 小时"时，实际可能已经 4 小时。要么标注"截至 HH:MM"，要么只在年轮用。

4. **年轮公告的日期窗口**
   12/20–1/15，靠本地时钟。用户改系统时间就能提前看到（这是测试手段，也是漏洞）。不修，因为它不是安全问题。

## 8. 三层纠错：落地情况

代码在 `src/index.html`，状态存 `data.json` 的 `fb / hide / gap / gapOff / said / saidN / vote` 七个字段。
**全部本地，不联网，不上报，没有任何统计端点。**

| 层 | 触发条件 | 用户能做什么 | 我承诺的后果 |
|---|---|---|---|
| 行级 | 任意一条来源行末尾的 `?`（鼠标经过才显形） | 数不对 / 不该显示 / 没事 | 「不该显示」→ 该行永久消失，`tip` 里相关判断同步闭嘴；「数不对」→ 记一条证词，**但不改数**（改了就成假账），年轮页显示"你纠正过我 N 次"，可一键恢复被藏的行 |
| 日级 | 日历当天 ≥2 个日程 **且** 账本 0 件 **且** 当天没问过 | 没做事 / 忘了记 / 别问 | 「忘了记」**不补数**，只给这天盖「可能漏记」的戳，年轮页如实写"其中 N 天你自己标了可能漏记，那几天按 0 算"；「别问」→ 14 天静默 |
| 月级 | 每月 1–7 号，列出上月**实际说过**的判断句 | 准 / 不准 | 同一类判断累计 **2 次"不准"→ 永久静音**，以后只给数、不给话（`muted()` 在生成时就拦掉，不是渲染后隐藏） |

三条设计约束，写在这里防止以后自己破坏：
1. **不改用户的数**。纠错只记录"你不信这条"，不修改数据本身。
2. **不补用户没记的**。"忘了记"只标瑕疵，不填数字。
3. **能被说到消失**。判断句不是文案，是可被否决的断言；否决够了就不说。

已验证（headless，20 条断言全过）：对账出现/回答后不再问/漏记标注/投票出现/投两次后该句消失/`?` 展开/隐藏某行/恢复隐藏/无 JS 报错。

## 9. 全量审查（2026-11-05）：每个数字的边界

用户要求「谨慎严格审查全量，明确边界，禁止伪证」。这次不是写原则，是逐个函数过一遍：
**任何一个显示给用户的数字，都要能回答"这个 0 到底是什么意思"。**

### 9.1 找到并修掉的四个真问题

| # | 位置 | 原来的行为 | 为什么这是伪证 | 改法 |
|---|---|---|---|---|
| 1 | `heatSvg` / `sevenBars` / `thirtyBars` | 没记录的日子一律画成「0 件」的浅色格 | 把"我不知道"画成了"你那天没做事"。用户会把空白读成事实 | 三态：**空白/描边 = 没记录**，**浅填充 = 已知是 0 件**，**淡化 = app 还没开始用那一段**。新增 `state.seen` 记「这天 app 开着」，只在 App 启动/跨天时盖戳，不记任何内容 |
| 2 | `staleCount` | `due <= 七天前` 判"躺了一周" | **这句话永远说不出来**：`rollover()` 每晚把没做完的 `due` 改写成今天，条件恒假。等于常年骗自己"没有积压" | 改用 `carried`（跨夜顺延时累加），文案改成「已经被往后推了一周以上」 |
| 3 | `projLine` | 用 byProj 的合计当分母算百分比 | byProj 是「项目」功能上线后才开始记的，早于它的完成没有归属。6 件里只有 5 件挂了项目时，报出「A 项目 60%」会被读成"占全年 60%" | 传入全年完成数；`sum < total × 0.9` 时不报百分比，只写「还算不了：只有 5 / 10 件挂过项目」 |
| 4 | `streakDays` / `yearStats.longest` | 连续天数把"不认识的日子"当断点继续或中断 | 中间一段没有记录时，说「连着 7 天」是编的 | 碰到未观测日**必须断开**。于是这个数是**下界**（真实值只会更长），结语里写明「连续天数也只数看得见的天」 |

### 9.2 「每天自动进入历史统计」对不对

用户问的是：账本每天记下来的东西，自动流进所有历史统计（含 2026 年轮页），对吗？

**一半对，一半必须拦。**

- **对的**：凡是**真实记录过**的，就该原样流进所有统计——不筛选、不回改、不按今天的口径重算。这是账本的意义。做过 6 件就是 6 件，昨天做的和今天做的权重一样。
- **必须拦的**：**没记录的日子不能被当成 0 件**。这不是谨慎，是逻辑：`daily` 里没有某个键，只说明"我没写"，不说明"你没做"。原来的代码把这两种情况都读成 0，于是分母被撑大、热力图被填满、连续天数被拉断——三处同时伪造。

所以现在的口径是三段，任何统计函数都必须先问自己落在哪一段：

| 段 | 判据 | 能不能当 0 用 |
|---|---|---|
| 已有数据之后、有记录 | `daily[k] > 0` | 不是 0 |
| 已有数据之后、没记录 | `seen[k]` 或 `flow[k]` 存在但 `daily[k]` 空 | **可以**：这天 app 开着，且账本没进账 |
| 已有数据之前 | 早于 `dataStart()`（最早的一条数据） | **不可以**：那时候这个工具还不存在 |

`dayObserved(day)` 就是这条规则的唯一实现。以后加任何新统计，都必须先调它。

### 9.3 自查清单（改统计代码前先过一遍）

1. 这个数的**分母**是什么？是日历天数，还是"我看得见的天数"？
2. 为 0 的时候，它表达的是「做了 0 件」还是「不知道」？两者能不能在界面上区分？
3. 这个功能是**后加的**吗？那它覆盖的历史是不是只有一部分？部分覆盖时还能不能报百分比？
4. 这个字段会被**系统自动改写**吗？（`due` 就会）改写过之后还能拿它回看历史吗？
5. 边界样本（1 天、0 件、只有 1 条）时会说出什么话？会不会说出"日均 6 件"这种荒唐话？

### 9.4 明确不做的（能力即负债）

- 窗口标题 / 剪贴板 / 摄像头：永不做（见第 1 节 L4）。
- 用 `due` 反推历史计划：永不。（`due` 每晚被改写，等于拿今天的排期伪造昨天）
- 替用户补记漏掉的天：永不。「忘了记」只盖戳，不填数。
- 把"没记录"翻译成"休息日/零产出"：永不。

### 9.5 第二轮审查（同日）：口径一致性与写盘安全

第 9 节修的是"某一个数字"，这一轮查的是**同一份数据在不同页面会不会说出不同的话**，以及**数据本身会不会被写坏**。

| # | 位置 | 原来的行为 | 为什么必须改 | 改法 |
|---|---|---|---|---|
| 5 | `meetingVsDone`（有会/没会对照） | 把全年**没观测过**的工作日也算进"没会"那一组，`dayDone` 记 0 | 那些 0 不是"没做"，是"我不知道"。混进去会把"没会"组的日均稀释掉，最后得出「有会反而做得多」——这种结论比不给结论坏得多 | 两组都先过 `dayObserved(t)`；样本不足 5 天就不出这行 |
| 6 | `monthBars`（年页 12 根柱子） | 整个月没有记录时，悬浮写「X 月 · 0 件」 | 月级重演了日级的错误：把"这个月我还没开始记"说成"这个月一件没做" | 新增 `monthObserved(year)`；0 观测的月写「没记录」且不画柱 |

### 9.6 完全磁盘访问：从「没生效」到「真通了」的完整记录

不再靠猜，让 app 把真实错误码打出来。第一次测到的日志长这样：

```
ext cal=ok/2/2d rem=ok/0open/0late screen=nofda/0s(rc=23 errno=1 sqlite=23:[authorization denied]) focus=8500s
```

读法：
- `rc=23` = `SQLITE_CANTOPEN`，不是"文件不存在"（那会是 `nofile`）；
- `errno=1` = `EPERM`，权限被否；
- `authorization denied` 是 TCC 层给的原话。

三者同时出现 = **TCC 在文件打开那一刻拒绝**，不是路径错、不是 WAL 缺文件、不是表结构不对（那会是 `noschema` + 别的 errno）。
另外 `designated requirement` 校验过：`identifier "local.desktodo.app" and certificate root = H"3fe5…"`，不含 cdhash，重建不会掉权限；`codesign --verify --deep --strict` 退出码 0。

**转折**：同日 09:43，设置页那次改动在认证框里走完之后，同一份代码、同一条命令变成：

```
ext cal=ok/2/2d rem=ok/0open/0late screen=ok/24987s focus=8604s
```

界面上的 `屏幕 6 小时 56 分 · 最多 WeChat 2 小时 22 分` 与 24987 秒对得上，`需完全磁盘访问` 那行自动消失。

所以这条链路上真正的坑只有一个，值得写下来：
**TCC 改「完全磁盘访问」要求一次系统认证；认证没走完时，列表里的开关看起来是开的，实际没落库。**
以后遇到"开关是绿的但仍 `nofda`"，先看 `errno`：`EPERM` 就是没授权（去做认证 / 删了重加），能打开但读不了（`noschema`）才是表结构问题。

顺带修掉一个 UX 死路：`openPrivacyPane` 原来优先用 `PrivacySecurity.extension` 这个新 scheme，
在 macOS 27 上它会被 `open` 接受却落在「连接」页——点了等于没反应。现在旧 scheme 优先，实测能直接定位到「完全磁盘访问权限」那一页。

### 9.7 节日 / 周末 / 人在不在（第三批数据源）

用户提了两件事：日历要标出「节日、法定、周末」，以及「键鼠空闲和锁屏/睡眠状态可加」。两件都按同一条规矩办——**只读系统里已经存在的真实数据，不内置任何表**。

**节日只能来自日历。** 放假和调休每年由国务院公布，写死在代码里第二年就是编的。所以：
- 识别用户日历库里名字含「节假日 / holiday / 假日 / 節日 / festival」的那本日历（macOS 上通常是订阅的《中国大陆节假日》）；
- 把它里面的**全天事件**当作节日名，产出 `holi: {"2026-10-01": "国庆节", …}`；
- 没订阅这本日历 → `holi` 为空、`hcal` 为空，页面就不显示节日，**不拿假表兜底**。
- 实测这台机器：`holi=44[中国大陆节假日]`。（这个 44 后来被证明是个误导，见 9.8。）

顺手纠正一处脏数据：节日全天事件原来被算进 `allday`，于是「另有 50 个全天」把 44 个节日当成了用户自己的日程。现在节日从 `allday` 里摘出来单独计，`allday` 只剩自己的。

**周末不显示，但一定排除。** 理由：
- 显示「周六」价值极低——窗口顶上就有日期和星期；
- 真正会出错的是统计：`meetingVsDone`（有会/没会对照）里，周末和节假日都会被稀释成「没会那天做了 0 件」。所以这两类日子在计算时排掉，且这行加了 `title` 写明口径「只比看得见的工作日：周末和节假日都不计入，节日取自「XX」日历」。
- 口径要能在原地看到，不能只写在文档里。

**键鼠空闲 / 锁屏 / 睡眠**（`src/Session.swift`）：只回答「有没有输入、锁没锁、睡没睡」，不记录按了什么、点在哪、窗口里是什么。
- `idleSeconds`：`CGEventSource.secondsSinceLastEventType(.combinedSessionState, …)`，系统只给时长；
- `isLocked`：`CGSessionCopyCurrentDictionary()["CGSSessionScreenIsLocked"]`；
- `displayAsleep`：`CGDisplayIsAsleep`；
- `systemAsleep`：`NSWorkspace.willSleep/didWake` 通知维护，不轮询。

用途只有一处，但很关键：**前台计时器（FocusTracker）在锁屏/熄屏/睡眠期间停止累计**。不改这一条，锁屏一夜就会产出「最多 Arc 8 小时」这种假数——比不给数据坏。
**不用空闲时长剔除前台时长**：看视频、读长文档时键鼠同样静止，按空闲剔会把真实使用抹掉。空闲只作为状态字段备着（`ext.session`），明天做 UX 时再决定怎么用。

**FocusTracker 是什么**：每 20 秒看一眼前台是哪个 app，把时长记进 `focus.json`（只记 bundle id + 秒数，不记窗口标题、不记内容），留 **7 天**（原为 30 天，9.8 收紧）。它是「系统屏幕使用时间读不到」时的兜底。
既然完全磁盘访问已经通了，它现在**默认不启动**（`setNeeded(screenOk == false)`）：两个都读会得到两套「今天用了多久」，页面只能二选一，那不如一开始就别采第二份。FDA 哪天失效，它会自动接管。

### 9.8 「节日 44 天」是错的：44 里一半是节气

用户问了一句「节日 44 天什么意思？按今天距离年底应该是 55 天吧？」。这一问问倒了三个东西。

**44 既不是倒计时，也不都是节日。** 把 `holi` 的键打出来看（`defaults write local.desktodo.app dbgHoli -bool true`）：

```
2026-01-01=元旦   2026-01-04=元旦（班）  2026-01-05=小寒   2026-01-20=大寒
2026-02-04=立春   2026-02-14=春节（班）  2026-02-15=春节（休）  2026-02-16=除夕
2026-02-28=春节（班）  2026-03-03=元宵节  2026-03-05=惊蛰
```

44 = 这本《中国大陆节假日》日历里**有条目的日期数**，其中明确放假 7 天、调休上班 6 天，剩下的 31 天是 **24 节气 + 元宵/除夕这类非假期节日**。所以「节日 44 天」这句话两处都错：数字不是天数倒计时，词也不是节日。

处理：
1. **年页删掉这一项统计。** 它不是「我这一年干了什么」，放进年轮里没有解释力，还会被读成倒计时。节日只在**今天真是节日**时说一句。
2. **给节日加类型。** 新增 `hoff: {日期: 1|0}`——`1` = 标题带「（休）」明确放假，`0` = 带「（班）」调休上班，**没标记 = 不知道**。
3. **今日行的文案跟着类型走**：`元旦 放假 · …` / `元旦 调休上班 · …` / `小寒 · …`（节气只报名字，不暗示放假）。

**顺带修掉一个假结论。** `meetingVsDone`（有会/没会对照）原来按「名字出现在节假日日历里」一刀切排除，等于把 **24 个节气日**（正常工作日）也从样本里删了。现在的规则是「只比**确定**的工作日」：

- 周末 → 不进样本；
- `hoff === 1`（明确放假）→ 不进样本；
- **有名字但没标休/班** → 不进样本。除夕（放假）和小寒（上班）混在同一堆，凭名字分不出来；分不出来就不当样本；
- `hoff === 0`（调休上班）+ 无条目的普通工作日 → 才算。

宁可样本少到出不了这行，也不拿不确定的日子凑出一个「有会反而做得多」。

**关于「接一个外部日历」。** 不需要写任何网络代码：macOS 的「日历」本身就是聚合器，它已经把《中国大陆节假日》作为可订阅日历提供（这台机器上就在）。所以在「设置 › 日历 › 添加日历 › 添加节假日日历」里勾一下，本工具立刻就能读到——**这条链路已经通了，接的是系统日历，不是我另写一个 API**。反过来，任何时候都不要在代码里内置节日表：放假和调休每年由国务院公布，写死第二年就是编。

**同日收紧的另外三处：**

| 位置 | 原来 | 现在 |
|---|---|---|
| 收起态「今天完成 N 件」 | 按 `due === 今天 && done` 算（昨天到期、今天才勾的会漏） | 走 `dayDone()` 账本，与进度环同一个数 |
| 年轮公告 | `__tick` 每秒调一次，每次都扫满 365 天 | 一天只判一次（跨天 key 变才重算） |
| `focus.json` | 读失败静默清空 → 下次 flush 用空表覆盖；写失败也吞掉 | 读失败则本次不写；写失败保持 dirty 下拍重试 |

**数据安全的最后一道口子也补了。** `readStore` 原来两个文件都读不出来就返回 `"null"`，前端当成新用户显示空清单——接着任何一次操作 persist 一遍，真数据就没了。现在：读不出来先把原文件**改名保留**成 `data.corrupt-时间戳.json`，再退备份；写盘失败由原生回执给页面，弹「保存失败：这次改动没写进磁盘」。

```
  src/AppDelegate+*.swift  8 个扩展：Chrome / Weather / Appearance / Dot / Files / Window / Menu / Sources / Bridge
  src/DesktopDot.swift  圆点、气泡、窗口基类（纯视图，不认识待办数据）
  src/Storage.swift     唯一知道数据在哪、怎么写、怎么导出、怎么删的地方
  src/Session.swift     键鼠空闲 / 锁屏 / 睡眠（只管"人在不在"，不记内容）
  src/sources.swift     日历（含节日） / 提醒事项 / 屏幕时间 / 前台计时
```

两条纪律：
- **前端只能在 `tools/bundle.sh` 之后跑**，且分片必须共享同一个 IIFE 闭包。想真正模块化就会撞上 WKWebView 的 `file://` CORS，不值得。
- **改 Swift 才用 `build.sh`**；只改页面用 `tools/hot.sh`。后者不重签名，已授的权限不动。

## 12. 本地优先的四条硬线，以及怎么把这个东西发给别人（2026-11-06 下午）

### 12.1 为什么是这四条

"本地优先"不是一个技术约束（不上传），而是一种**可验证性**：
联网产品的每句承诺都要靠用户相信，本地优先的每句承诺都能被用户当场拆穿。

所以它要做的不是"保护隐私"，而是**把每句承诺做成一个用户能自己做的检查**
（详见第 11 节那一版讨论）。四条硬线，缺一条就不成立：

| 承诺 | 用户怎么验 | 现在 |
|---|---|---|
| 不联网也能用 | 拔掉网线，功能不减 | ✅ 天气是唯一出口，失败不污染任何数字 |
| 数据是普通文件 | 打开 `data.json` 直接读 | ✅ 纯 JSON，字段名是人话 |
| 数据带得走 | 导出一份，不依赖这个 app | ✅ 菜单「导出全部数据…」 |
| 删了就是没了 | 删完在目录里看不见副本 | ✅ 菜单「清空全部数据…」 |

### 12.2 导出为什么是这个形状

导出的验收标准只有一条：**把这个 zip 发给一个不懂代码的人，他能自己回答
"我这几年干了多少、从哪天开始记的"。**

所以包里是 `data.json`（原样字节拷贝）+ `读我.md`，不是数据库、不是加密包。
`读我.md` 必须自带四样东西，少一样就等于把解释权留在了这个 app 里：

1. **格式版本号**（`v: 2`，写进 json 也写进说明）；
2. **逐年逐月的数字**，而且空缺的月份必须写 `—` 不能写 `0`；
3. **字段表**（`daily` / `seen` / `flow` 各是什么，别处查不到就完了）；
4. **口径声明**（没记录 ≠ 0 件、历史不回改、不替你补记）。

最后一条最容易被略过，但它是这份文件的重点：数据本身活了，
**口径没跟着走，拿到 json 的人仍然会把它读错**。

两个实现细节，都是踩出来的：
- `ditto` 必须带 `--norsrc --noextattr`，否则解压出一堆 `__MACOSX/._*`；
- 导出前主文件不可用时，退到 `.bak` 或当前内存数据——**宁可导出备份，也不能导出空包**。

### 12.3 清空为什么必须"真删"

`wipeAllData()` 删的是：`data.json`、`data.json.bak`、`data.corrupt-*`、
早期的 `data.backup-*`、`focus.json`。不进废纸篓、不留副本。

少删一类的后果不是"占空间"，而是**那条承诺变成假的**：用户以为删了，
其实硬盘上还有一份能恢复的完整历史。所以清空之后实测过目录——
只剩一个页面重写的空 `data.json`（197 字节），没有任何旧数据残留。

顺带修的一个小漏洞：清空后 `seq` 还是旧值（57），等于把"你以前建过 57 个条目"
继续写在文件里。现在 `__load(null)` 会把 `seq` 一起归 1。

### 12.4 分发：三条路，只有一条"双击就行"

这是这个产品第一次离开本机，卡点不在代码在签名。如实写：

| 方案 | 对方要做什么 | 代价 | 结论 |
|---|---|---|---|
| **A. Ad-hoc 签名 + 安装脚本** | 右键「打开」一次 | 每次更新要重新授权日历/提醒（签名变了） | ✅ 现在用这个 |
| B. Apple Developer ID + 公证 | 双击 | 99 美元/年 + 账号 | 验证留存之后再买 |
| C. 让对方自己 `swiftc` 编 | 装 Xcode 命令行工具（1GB+） | 太重，体验官不是开发者 | ❌ |

**为什么分发包绝不能用本机的固定自签证书**：那张证书的私钥在本机钥匙串里，
带着它签名等于把签名身份一起送出去；而且对方的机器不认这个根，装上也跑不起来。
`build.sh`（自签，为了重建不掉 TCC）和 `tools/dist.sh`（ad-hoc，为了谁都能跑）
是两条互不干扰的路。

分发包里四个东西，缺一个对方就会卡住：
- `浮窗待办.app`
- `安装.command` —— 拷到 `~/Applications` + `xattr -dr com.apple.quarantine` + 打开
- `读我.txt` —— 没有 Dock 图标这件事必须写，否则对方以为没装上
- `体验清单.md` —— 见下

`spctl -a` 对分发包返回 `rejected` 是**预期结果**（没公证），
所以安装脚本里去隔离属性那一步不是可选优化，是必需品。

### 12.5 反馈：只收计数，不收内容

本地优先的产品不能用埋点，也不该为了拿反馈去搬用户的东西。
所以反馈通道是两条，都由用户主动触发：

1. **「复制诊断信息」** —— 剪贴板里一段纯文本：版本、清单条数、账本累计、
   各来源的 `st` 枚举（`ok/ask/nofda`）、会话状态、数据文件状态、窗口尺寸、
   你纠正过我几次。**没有一个字的任务内容、日历标题、文件名、app 名。**
   这条边界写在 `10-data.js` 的注释里，改的人能看见。
2. **「导出全部数据…」** —— 完整数据，但只在用户主动点、主动发的时候才离开机器。

`体验清单.md` 的四个问题按价值排序，第一条最重要：
**"第一次打开后的 30 秒内，有没有一次'这是干嘛的？'"**
——这条比任何功能建议都值钱，因为它决定这个人会不会用第二天。

### 12.6 这一轮实测记录

| 验的东西 | 怎么验的 | 结果 |
|---|---|---|
| 导出包完整性 | `dbgExport=/tmp/x.zip` 启动自动导，`ditto -x` 解压 + `json.load` | 2 个文件，`v=2`，17 个键全在 |
| 说明文件正确性 | 逐段读 | 逐年数字对得上账本；无记录月写 `—` |
| 恢复路径 | 把 `data.json` 写成半截 JSON | 原文件留证为 `data.corrupt-*`，自动退 `.bak`，状态条出现（截图核对） |
| 恢复后自愈 | 同上 | 已用备份重建主文件，下次还有"上一版"可退 |

**没验到的**：Developer ID 公证那条路没走过（没有账号），所以"双击就能用"
这句话现在还不成立，只能说"右键打开一次就能用"。

## 13. 开源与分发：把边界做成能失败的检查（2026-11-06 下午）

### 13.1 为什么不靠"文档里写了不做"来守边界

一个 PR 加一行 `URLSession`，就能让"数据不出机器"从事实变成口号，
而 CI 全绿、界面照旧、用户完全察觉不到。文档不会拦人，**能失败的检查才会。**

所以 `tools/audit.sh` 把六条边界做成了检查，任何一条红就不发版：

| 检查 | 拦住的事 |
|---|---|
| 网络出口白名单 | Swift 里除 `AppDelegate+Weather.swift` 外出现任何 `URLSession/URLRequest/CFStream` |
| 域名白名单 | 只准 `api.open-meteo.com` / `ipwho.is`，出现在别的文件也算红 |
| 页面网络 API | `src/js` 里出现 `fetch/XMLHttpRequest/WebSocket/sendBeacon` |
| 反遥测关键词 | `analytics/telemetry/sentry/firebase/umeng…` |
| 权限面锁 | `Info.plist` 的键必须落在固定名单里，**多要一个权限就构建失败** |
| 数据不入库 | 被 git 跟踪的文件里出现 `data.json` / `*.bak` / `*.keychain*` / `dist/` / `build/` |
| 口径唯一 | `dayDone` / `dayObserved` 各只许一处实现；不许绕过它们直接翻 `dailyMap()` |

最后一条是这半年的教训换来的：三次"没记录被算成 0 件"，根源都不是算式写错，
而是同一件事有两份实现，改了一份忘了另一份。

### 13.2 联网这件事，从"承诺"变成"开关"

原来唯一的对外连接是天气，验证方式只有一句"你信我"。现在菜单里有
**「不联网（天气停更）」**，打开后 `refreshWeather` 第一行就 return，
并把缓存的温度一起删掉（留着旧温度，等于让人以为它还在更新）。

可验证性实测（这是这一节的重点，不是修辞）：

```bash
# 关闭联网
lsof -nP -a -p $(pgrep -f DeskTodo) -i     → 无输出（退出码 1）
# 恢复联网、清掉缓存再启动，同一条命令
lsof -nP -a -p $(pgrep -f DeskTodo) -i     → 抓到一条 TCP（经本机代理）
```

同一台机器、同一个命令、两种结果。**这就是"可验证"和"请相信我"的区别。**

### 13.3 许可证拆成两半

- **代码 MIT**：能读、能改、能再用、能提 PR、能拿去学。用限制换不来好感。
- **名称/图标保留**（见 `NOTICE.md`）：改装后要分发，请换名字、换图标、改 bundle id。

理由不是法律洁癖：同名的两个东西用户分不出来，一个被加料的同名构建
坏了的是原作者的名声，而用户以为他装的是"那个本地优先的工具"。
bundle id 这条还有技术原因——macOS 的权限按 bundle id + 签名记，
撞 id 会让两边的日历授权互相打架。

### 13.4 分发两条路，泾渭分明

| | `build.sh` | `tools/dist.sh` |
|---|---|---|
| 签名 | 本机固定自签证书 | ad-hoc（`codesign -s -`） |
| 换来的 | 重建不掉 TCC 权限 | 任何 Mac 都能跑 |
| 代价 | 只有这台机器认 | Gatekeeper 拦一次，且每版更新要重新授权 |

分发包**永远不能**用本机证书签：私钥不外传，且对方机器不认这个根。

### 13.5 复盘：这一轮踩到的两个真问题

1. **重建后日历/提醒授权掉了**（`cal=ok` → `cal=ask`），而完全磁盘访问还在。
   DR 字符串前后完全一致（`identifier "local.desktodo.app" and certificate root = H"3fe5…"`），
   所以不是签名漂移；更可能是用户在系统设置里删除并重新添加 app（修 FDA）时，
   tccd 顺带重置了同一 bundle 的其它条目。**结论：授权是按条目存的，不是按 app 整体存的。**
   处理方式不是改代码，是在菜单「数据来源 → 请求日历授权…」点一次允许——之后重建不再问。
2. **CI 第一次就是红的**：`swiftc -o build/DeskTodo-ci` 失败，`errno=2`。
   原因很朴素——`build/` 不入库，新克隆里没有这个目录。这条恰好证明 CI 有用：
   本机永远有 `build/`，所以这个错只有别人克隆时才会犯。

### 13.6 不做什么（分发层面）

- 不做自动更新器：一个能自己下载并替换自己的机制，是本地优先产品的反向操作。
- 不在 CI 里签名发 release：分发包必须由维护者在自己机器上产出并贴 sha256，
  否则"官方构建"这四个字没有对应的责任主体。
- 不收集下载量/安装量：GitHub 自带计数，没必要为此加一行代码。
