## 1. P0：会让账目永久出错的（已修）

这三条的共性是：**错了以后用户看不见，而且越用越错。**

### A1. 取消勾选一件 60 天前完成的任务，账本永久多记一件

**现象**

`05-today.js` 的 `pruneLog()` 只保留最近 60 天的完成明细：

```js
var cut = todayStart() - 60 * 86400000;
state.log = logArray().filter(e => e.at >= cut);
```

而取消勾选靠的就是这份明细，去账本里减掉那一笔：

```js
function markUndone(t) {
  t.done = false;
  delete t.doneAt;
  for (var i = log.length - 1; i >= 0; i--) {
    if (log[i].id === t.id) { bumpDay(log[i].at, -1); ... break; }
  }
  // 找不到 → 循环走完，什么也没发生
}
```

超过 60 天，`log` 里没有这条，循环走完什么都不做，**`daily` 不减**。

**为什么不是小事**

`daily` 是这个产品唯一的账本，热力图、月柱、年轮、日均、连续天数全部读它。
多记一件不会报错、不会提示、界面上完全正常——只是所有数字从此偏高，
而且**没有任何办法发现是哪一天错的**。这直接打穿"账目可以被你自己核对"这个前提。

**修法**

`doneAt` 一直挂在任务对象上，不随 `log` 裁剪。找不到明细时用它兜底：

```js
var at = hit >= 0 ? log[hit].at : (typeof wasAt === 'number' ? wasAt : 0);
if (at) { bumpDay(at, -1); bumpProj(t, -1, at); }
```

代价写清楚了：60 天前的取消勾选只能退到"天"，退不到"秒"（`log` 里有秒，`doneAt` 没有）。
秒只影响"什么时段出活"那一个统计，不影响任何账目数字。

**怎么验**：`tools/check.js` 用例「账本自洽」第 1 条——
造一条"60 天前完成、`log` 为空、`daily` 里是 1"的数据，点取消勾选，断言 `daily` 里那个键消失。

### A2. 顺延天数会自己变小：累加上界 999，重算上界 366

**现象**

`02-plan.js` 的 `rollover()` 里，同一个数有两套上界：

```js
// 重算：老数据被算爆过，按真实创建日折回
if ((n.carried || 0) > 366) {
  var real = Math.round((t0 - dayStart(n.created)) / 86400000);
  n.carried = Math.min(real, 366);        // ← 366
}
// 累加
n.carried = Math.min((n.carried || 0) + Math.max(1, gap), 999);   // ← 999
```

一条真拖了近一年的任务，`carried` 会涨到 400、900；
下次启动 `> 366` 成立，被折回 366。**用户会看见「顺延 900 天」自己变成 366 天。**

**为什么不是小事**

`docs/PRODUCT-BOUNDARY.md` 和 `README.md` 都把这条写成了硬承诺：

> **历史不回改。** 今天的口径变了，去年的数字不跟着变。一旦用户发现记的东西会变，他就不会再记了。

`carried` 不是历史统计，但它是**展示给用户的数字**，而且这次变小的方向是"把欠账说轻"。
一个账本可以难看，不能自己改数。

**修法**：累加上界改成 366，和重算一致。两条路的上界必须是同一个常量。

**怎么验**：用例「账本自洽」第 2 条——造 `carried: 900`，断言 `carried <= 366` 且不等于 999/900。

**没做的部分**：366 这个数本身没有产品依据，只是"一年"。真正的做法是
`carried` 不封顶、但界面只显示"一年以上"。这需要改文案，留到下个版本。

### A3. 只做过销账的那一天，会从"知道"退回"不知道"

**现象**

`dayObserved(day)` 判定"这天我看得见"有三条证据：账本有数、`seen` 有戳、流水有操作。
1.3.0 加了第三种操作"认赔"（`q`），但判定只数前两种：

```js
return !!(f && ((f.n || 0) + (f.x || 0) > 0));   // 没有 q
```

**为什么不是小事**

`seen` 只留 800 天（`markSeen()` 里裁剪）。800 天后，一个"当天只销了账、没新建没完成"的日子
会从"知道是 0 件"变成"不知道"——热力图从浅色变描边，日均分母变小，连续天数断开。
**这正是这个产品反复声明"绝不混淆"的那两件事。**

实际触发概率很低（`seen` 要裁到 800 天前，且那天只有销账），但口径错误不分概率高低：
口径只该有一个定义，多一个例外就是以后每一处都要记得这个例外。

**修法**：三种操作都算证据，`q` 并进去。口径只加不减，老数据不重算。

**怎么验**：用例「账本自洽」第 3 条——`daily` 空、`seen` 空、`flow` 只有 `{q:1}`，
断言年轮热力图那一天的提示不含"没记录"。

## 2. P1：说了做不到的（已修）

这一类比 P0 更伤，因为它不是算错，是**产品在撒谎**。

### B1. "这行以后会被我记得不牢" —— 没有任何代码这么做

`07-truth.js` 的 `doFb('wrong')` 点完之后弹出：

> 记下了 · 这数我不改（改了就成假账），但这行以后会被我记得不牢

查遍全仓库：`state.fb` 只在两个地方被读——`fbStatHtml()` 读 `.length` 显示"你纠正过我 N 次"，
`diagText()` 读 `.length` 写进诊断信息。**没有任何分支会因为 `fb` 改变输出。**

能改变行为的只有月级投票（`saidN`），那条路径跟 `fb` 不通。

**修法**：改文案，指向真实存在的行为——

> 记下了 · 这个数我不改（改了就成假账）。年轮里那句判断，你可以在下面投「不准」

顺带把 `10-data.js` 导出说明里同一处假话改掉：字段表原来写
"`hide` / `fb` / `saidN`｜你否掉过的来源行、判断句。你没说错的会一直闭嘴"。
实际只有 `hide` 会让一行闭嘴，`saidN` 会让一类判断闭嘴，`fb` 只是存档。

### B2. `diagText` 的注释和它的输出不符

注释写"只写 ok / ask / denied 这类枚举，不写读到了什么"，但同一段代码里有：

```js
(s.sec !== undefined ? ' · ' + Math.round(s.sec / 60) + ' 分钟' : '')
```

它输出了屏幕使用时长。**这不是泄露**（分钟数不含任何内容，末尾那句"不含任何任务内容"
是准确的），但注释失真会让下一个开发者以为这里不该有秒数，顺手删掉，反而破坏诊断能力。

**修法**：注释改成准确的说法——"只写枚举和用量，不写任何内容（标题、文件名、任务文本）"。

## 3. P1：使用者根本看不见的（已修一处，一处未修）

### C1. 报告五个页签高度从 200px 到 700px，切一次窗口弹一次

今日页约 200px，年轮页约 700px。`toggleReport()` 每次都 `lastHeight = 0` 并重新上报高度，
窗口跟着内容跳。切页签时眼睛在抖，窗口还可能被推出屏幕边缘。

**修法**：加一个"只增不减"的高度锁（`07-truth.js` 的 `lockReportHeight`）：

- 打开报告时按当前页签定高；
- 之后切页签，只可能变高，不会缩回来；
- 上限 640px，超过的自己滚。

为什么不用固定高度：试过 368px 定死，切页签绝对不抖，但今日页底下留 130px 空白，
卡片看起来像没做完。也试过 `min-height`，短页签还是会被撑出空白。
"只增不减"是唯一既不跳又不留白的做法——代价是切过年轮再切回今日会有留白，
但**窗口一次都不动**。这个取舍写在这里，不藏在代码里。

**怎么验**：用例「账本自洽」第 4 条——量 `day → yr → day` 三次的 `offsetHeight`，
断言只增不减、切回不变、上限 640。

### C2. 三层纠错里"最重要"的第三层，大多数人永远见不到（未修）

`voteHtml()` 同时满足四个条件才出现：

1. 日期在每月 1–7 号；
2. 用户打开报告卡；
3. 用户停在**年轮**页签；
4. `state.said` 里有上月的话——而 `said` 只在**年轮页签渲染时**才被写入。

也就是说：**打开年轮 → 才记录我说过什么 → 下个月 1-7 号再打开年轮 → 才有东西可投。**

`PRODUCT-BOUNDARY.md` 第 5 节把月级否决写成"最重要"的一层，实际触达路径长到几乎不会发生。

**为什么这次不修**：修它要动报告卡的信息层级（把投票提到日结条或报告卡顶部），
属于设计改动，不该混在诊断轮里做。记在这里，下个版本第一件事。

## 4. 结构隐患：渲染函数里写盘（未修）

`02-plan.js` 的 `renderAgenda()` 在渲染日结条时直接写盘：

```js
state.settle = dayKey(Date.now());
persist();          // ← 在渲染函数里
```

**风险**：`persist()` 会 `send('save', ...)` 把**当前内存中的整个 state** 写下去。
只要有一天 `render()` 在 `__load()` 之前被调用一次，磁盘上的 `data.json` 就被空状态覆盖。

**现在不会爆**，因为启动路径是 `原生 → __load() → render()`，`__load` 之前没有 `render()`。
但这是"靠顺序正确"而不是"靠结构正确"。`09-boot.js` 里已经出现过一次类似事故
（测试脚本 `__load(null)` 把数据清空），说明这条链很脆。

**正确做法**：渲染只读，写盘由调用方负责；或者 `persist()` 加一道"未加载完成则拒绝写盘"的闸门。
后者 5 行代码，建议下版做。

## 5. 性能退化：三处 O(n²)，任务一多就卡（未修）

`byId()` 是线性扫描（`01-core.js`）：

```js
function byId(id) { for (var i = 0; i < state.nodes.length; i++) ... }
```

它被用在循环里，于是变成平方级：

| 位置 | 频次 | 代价（300 件时） |
|---|---|---|
| `refreshChips()`：对每个 `.task` 调 `byId` | **每秒 1 次** | 约 9 万次比较/秒 |
| `render()` 里 `loose.filter(n => byId(n.parentId))` | 每次重绘 | 约 9 万次 |
| `rollover()`：每秒遍历全部节点 | **每秒 1 次** | 300 次/秒（线性，但白跑） |

1000 件时 `refreshChips` 每秒约 100 万次比较。这不只是卡——`__tick` 每秒跑一次，
意味着**每秒都在做一次全表扫描**，笔记本电池上看得见。

**修法**（下版）：维护一个 `id → node` 的 Map，在 `__load` / 增 / 删 / 移除时更新；
`refreshChips` 改成一次遍历 DOM 一次查 Map。预计删掉 60% 的空转。

## 6. 定位层面的张力（不是 bug，但必须写清）

### D1. 年轮里的"夸人话术"和"不评价"的定位冲突

`07-truth.js` 的 `tipYear()` 会在条件满足时说：

- "写下来的几乎都做完了，这比做得多更难。"
- "这个量不是靠热情撑住的。"
- "一百多天里动过手，这一年没白过。"

而 `docs/POSITIONING.md` 第 5 节给的判断标准是：

> 判断标准：**这一栏能不能被用户反驳**

按这条标准，上面三句都该删——用户无法反驳"这比做得多更难"。

**但它有一个出口**：这三句都走 `say()`，会登记进 `state.said`，下个月可以被投"不准"，
同一类被说两次不准就永久静音（`muted()`）。**这是这个产品里唯一"可被否决的判断句"机制。**

结论：保留，但性质要说清——它不是统计，是**可被否决的评价**，默认出现、可累积关掉。
这条界线不写进文档，下次有人看到"不评价"的定位会把它当 bug 删掉，或者反过来加更多。

### D2. "最长连续"永远是下界，但界面上写成一个确定数字
`yearStats()` 的注释明确写着：

> 没看见过的日子既不能接龙也不能算 0，只能当成断点。
> 所以这个"最长连续"是下界：真实值只会更长，不会更短。

但三处展示都没有"至少"：报告卡年轮页的「最长连续 N」、年轮公告的「最长连 N 天」、
导出表里的「N 天」。导出说明正文里倒是写了一句"所以「最长连续」永远是下界"，
但表格里的数字本身没有任何标记。

**建议**（未做）：改成 `≥ N`，或在数字旁加 `?` 提示。纯文案改动，但会动 3 个文件。

### D3. `⌘H` 不是"隐藏应用"，是这个 app 的"收起"

`AppDelegate+Menu.swift` 给「收起悬浮窗」挂了 `keyEquivalent: "h"`，没设 `modifierMask`，
默认就是 `⌘H`。在 macOS 上这个组合是**系统的"隐藏应用"**。

结果是：用户按 `⌘H` 想隐藏窗口，实际发生的是"收成桌面右下角一个点"。
两件事视觉上差别很大，而且没有任何提示说明它被改了。

**建议**（未做，需要产品决定）：要么换成不冲突的组合（如 `⌘⇧H`），
要么保留但第一次触发时提示一次"已收成桌面小圆点，点它展开"。
现状已写进 `MANUAL.md` 第 10 节，至少不让用户以为系统坏了。

## 10. 这份诊断本身的边界

说清楚它没做什么，免得被当成"已经全面审过"：

- **没做渗透测试**。网络出口、权限面是静态检查，不是动态抓包。
- **没在旧版 macOS 上跑**。只在当前系统版本验过。
- **没测极端数据量**。1000+ 条任务是推算的，没有实测夹具。
- **Swift 侧只看了结构和数据流**，没有逐行审内存/线程安全。
- **没有真人用过**。所有结论都是代码与断言的结论，不是使用者的结论。
  真正的问题可能是"没人想打开它"，那不在代码里。
