# 定位

## 一句话

桌面上一本只记「你给自己派的活，最后做成了什么样」的日账本。

## 30 秒

它不催你多干，只帮你记准：每天派了几件、划掉几件、哪几件滚到了明天；年底翻回来是一本可以带走的账。

和待办软件的分界：它们问「还有什么没做」，它问「你欠自己多少」。

## 四个动作

| 动作 | 用户的话 | 它做什么 |
|---|---|---|
| 记 | 今天我要干这几件 | 回车就进清单；过夜的自动接到今天，并记一次顺延 |
| 划 | 干完了，划掉 | 记下划掉的时刻；划错了能退账 |
| 结 | 今天到底结了啥 | 每天第一次打开结一句；拖过两天的进欠账面板，能销账 |
| 稽 | 这一年到底干了什么 | 今日 / 本周 / 30 天 / 半年 / 年度；数字可被用户反驳 |

## 三条数据边界

1. **只读用量，不读内容。** 日历、提醒事项、屏幕使用时间、前台 App、登录会话都是系统已经算好的用量；不读窗口标题、剪贴板、截图、网页内容。
2. **用量只做对照，不做判断。** 例如「有会的日子 vs 没会的日子」只报数字，不下结论。
3. **前台 App 只记 bundle id 与秒数。** 只在屏幕使用时间读不到时兜底，7 天自动裁。

## 三条判断标准

新增任何功能之前，先过这三条；任意一条为「是」就不做：

1. 这一栏能不能被用户反驳？
2. 它会不会制造「第二份真相」（和账本数字对不上）？
3. 它会不会增加打断（推送、红点、弹窗）？

## 明确不做

番茄钟 / 专注计时、AI 拆解任务、自动补记、连续天数激励、排行榜、社交、云同步、窗口标题与剪贴板读取、内容级屏幕识别、主题商店、子任务树、标签体系、四象限、看板拖拽、团队协作。

理由：它们要么产生用户无法反驳的数字，要么把账本变成任务管理器，要么需要联网或内容级权限。

## 命名

- 产品名：DeskTodo（可执行文件、bundle、dmg 用 ASCII）
- 显示名：浮窗待办（`CFBundleDisplayName`）
- bundle id：`local.desktodo.app`（不动；改了会导致授权、登录项、数据路径全部失效）

## 数据承诺

- 数据只在本地，明文 JSON，可随时导出。
- 没记录 ≠ 0 件：空白的一天不会被算成「那天什么也没做」。
- 历史不回改：今天的口径只影响今天往后。
- 节日只认系统日历，不内置节日表。
